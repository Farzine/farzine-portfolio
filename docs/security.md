# Security notes (migration in progress)

Threats: anonymous/non-admin writes, draft/private content reads, forged sessions/roles, unsafe links/HTML/uploads, destructive media removal, contact abuse and shared-cache session leaks. Route hiding is never authorization. No hosted project was configured or modified.

## Implemented through Phase 4

- Every exposed content table has RLS, explicit grants and separate public-read/admin-write policies. Private UUID allowlist/provenance have no API-role table grants. `is_admin()` has fixed search_path, stable security-definer execution, authenticated-only execution and no recursive role policy. User-editable metadata/email confer no role.
- Published due projects only; private/draft/archive/future and hidden personal facts denied to anon/non-admin. Gallery requires public asset and published project. Skills require visible group. Section visibility is a display control; revoke item visibility/status to withdraw data.
- Versioned migration and non-destructive seed; historical projects draft and private fields invisible. Pure safe URL DB checks, unique slugs, publish timestamps, media-path/size/MIME constraints and restrictive FKs. No arbitrary HTML/SQL editing.
- Separate **server-only** public anonymous client (no session persistence) and SSR session client. `requireAdmin` verifies signed claims then calls UUID-role predicate for each privileged operation; never shared-cache authorization. No service-role key. Client browser bundles do not import the historical seed or auth/DAL modules.
- Auth is intentionally server-managed via Server Actions: SSR cookies HTTP-only, Secure in production, SameSite=Lax. No browser auth client is installed because JS need not read tokens. This differs from the optional browser-session example in provider docs and preserves HTTP-only cookies. Future OAuth/PKCE features must account for this choice; do not mix a cookie-reading browser auth client into this flow.
- Next 16 `proxy.ts` refreshes cookies on admin/auth paths only, forwarding provider cookie/cache headers. Admin paths get private/no-store + noindex. Server Components cannot write cookies; actions use `writeCookies: true`. Proxy does not replace `requireAdmin` at every mutation/privileged DAL boundary. Login/logout, actual refresh and direct-action denials are verified locally in Phase 4.
- Storage buckets: public display and private draft, admin-only writes; generated UUID paths and raster/PDF metadata limits. Public bucket bytes are always public; private assets require signed admin reads and explicit promotion. Server file-byte validation/reference-safe removal still Phase 5.
- Baseline nosniff/same-origin framing/referrer headers, noindex legacy preview. `.env*` ignored except safe example. Public config rejects secret/service keys and unsafe URLs without echoing values. Explicit seed mode allowed only development/test; no fake persisted writes.

## Phase 4 verification and boundaries

- Password login uses provider Auth, then checks verified identity plus the private UUID allowlist. Wrong credentials and unauthorized identities get the same generic message; failed authorization signs out the newly created local session. No emails/UUIDs/tokens are logged. Logout intentionally supports any session, including a revoked owner/non-admin, and reports failure honestly. Provider local-session logout does not invalidate access JWTs immediately; UUID-role removal blocks CMS operations independently of token expiry.
- Each settings/project/gallery Server Action calls `requireAdmin` before processing input. Each privileged DAL function independently authorizes. Read guards redirect unauthenticated/non-admin requests before fetching private data; layouts are additional navigation gating. Tests capture actual authorized action POSTs and replay their exact body/action ID without cookies and with a real non-admin session; all core CMS operations deny both. A deliberately foreign Origin is rejected by Next; expected rejection is logged on the test server, with no application success.
- Zod enforces URL schemes/credentials/control characters, length/list/count limits, UUIDs, lower-case slugs, enums, publication times, integer ordering and CTA pairs. Only declared fields are read; user-supplied role/timestamps are excluded. Plain text is escaped by React, including tested script text. Invalid/duplicate slugs and private image publication fail without altering stored content. Settings/project updates and deletes match `updated_at` atomically to reject stale forms. Private draft previews use guarded routes and no shared cache; public readers always use their anonymous client.
- Real Chrome/provider checks cover incorrect password, rejected forged admin metadata, closed registration (`signup_disabled`), login/logout and HTTP-only/Secure/SameSite cookies inaccessible to `document.cookie`, cookie refresh after forced local expiry and invalid-cookie recovery. Local provisioning has a separate loopback-only test script; the app receives no operator key. Only publicly documented fixture passwords are committed, never usable production credentials. Never upload ignored browser traces; they contain session/action material.
- Provider rate limits remain enabled. Review hosted password/login limits, abuse monitoring and MFA/SMTP/invite recovery before deployment using [official rate-limit guidance](https://supabase.com/docs/guides/auth/rate-limits). This phase adds no distributed application limiter; final deployment abuse controls remain Phase 7. Global registration stays disabled while the email provider is enabled; [local configuration notes](supabase.md#email-provider-configuration-and-local-owner-tests) explain the misleading provider switch name.
- A scan of 16 client JavaScript chunks found none of the dedicated Auth fixture credentials, private canary or seed provenance. App modules do not import the provisioning script or receive its operator key. Exhaustive secret/history/build/config review is Phase 7. No file upload endpoint or public message-submission endpoint exists yet. No hosted project/push/deployment occurred.

CMS browser tests use an exclusively owned app process on reserved port 3102 and reject non-loopback provider configuration. They refuse existing-server reuse; an unrelated process on development port 3000 was left untouched. The final full regression passed on this isolated test origin.
